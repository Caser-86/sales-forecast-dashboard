# Interview-Ready MVP Design

## 目标

将当前销售预测 Demo 提升为可在面试中完整讲解的 MVP：能说明业务问题、展示模型可信度、支持可复现的筛选交互，并明确生产化边界。

## 范围

### 1. 模型与数据可信度

- 训练报告保留现有 `lstm`、`lightgbm`、`ensemble` 指标。
- 增加 7 日季节性朴素基线，用同商品同门店前一周同日销量与模型对比。
- 报告增加训练时间、数据时间范围、切分行数、特征数、预测周期和集成权重。
- 新增 `/api/model-info`，为前端和面试演示提供模型版本、数据切分和指标。
- 新增 `/api/data-quality`，展示数据规模、缺失、重复、日期断档和负销量检查。

### 2. Dashboard 交互

- `/api/dashboard` 和 `/api/inventory` 支持可选 `product_id`、`store_id` 筛选。
- Dashboard 增加商品范围、门店范围、刷新按钮和当前更新时间。
- 前端展示模型/数据状态，并对初始加载、刷新失败、空结果和按钮忙状态给出可见反馈。
- 不改变现有默认全量视图和既有响应字段。

### 3. 面试材料

- README 改写为项目案例说明，包含业务目标、架构、关键决策、指标、限制和运行方法。
- 增加 5 分钟演示脚本和常见追问，诚实区分生成数据 Demo 与生产系统。

## 非目标

- 本次不引入数据库、登录系统、在线训练队列或真实业务数据接入。
- 不把示例数据指标表述为真实生产效果。
- 不改动 Docker Desktop、WSL 或宿主机运行时配置。

## 验收标准

- 新增 API 有自动化测试，旧测试继续通过。
- 基线指标可从训练报告读取，旧报告缺少新字段时 API 仍能返回降级状态。
- 全量筛选结果与默认结果口径一致，单商品单门店筛选只返回对应范围。
- 前端 JavaScript 通过语法检查，API 请求失败时用户能看到错误而非只写控制台。
- Docker Compose 配置和主要 HTTP 端点可启动并返回成功响应。
