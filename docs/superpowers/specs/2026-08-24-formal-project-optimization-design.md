# 正式项目优化设计

## 目标

在不破坏现有 FastAPI 接口字段和 Docker 部署方式的前提下，修正大屏聚合口径，明确库存 ABC 分级规则，降低批量预测的冷启动耗时，并建立可以在 GitHub Actions 中重复执行的测试与静态检查门禁。

## 当前问题

1. `/api/dashboard` 的商品历史销量是所有门店汇总，但预测量和建议采购量只取门店 1，指标口径不一致。
2. ABC 逻辑的注释声称按预测总量分类，实际使用最近历史销量；同时使用浮点值匹配商品，存在重复值和浮点误差风险。
3. 批量预测按商品和门店串行执行，首次访问大屏时延迟较高。
4. 前端只识别 3000 和 5500 端口，其他本地开发端口无法可靠连接后端。
5. 仓库缺少从干净 checkout 开始生成测试数据、训练模型并执行检查的 CI 流程，README 中的模型指标也没有标注为可复现实验结果。

## 业务口径

- `total_sales`：原始销售数据最近 30 天、所有商品和门店的销量总和。
- `total_predicted`：所有商品和门店未来预测天数的预测销量总和。
- Top 商品的 `predicted` 和 `suggested_purchase`：同一商品在所有门店的对应字段求和。
- ABC 分级：使用原始销售数据最近 30 天的商品需求量，按商品汇总后排序，累计占比 `<= 70%` 为 A，`<= 90%` 为 B，其余为 C。零总量时全部为 C。该规则用于商品库存优先级，不与未来预测值混用。
- 单商品单门店预测接口和库存热力图继续返回门店粒度的 ABC；大屏 KPI 和 Top 商品返回商品粒度的 ABC 分布/等级。

## 设计

### 共享 ABC 领域函数

新增 `backend/common/abc.py`，提供接受映射并返回同键分类映射的纯函数。函数将负数按零处理，按数值降序并使用稳定的键字符串作为平局排序依据；分类结果通过键关联，不再通过浮点数反查。

预测器在加载原始数据时预计算最近 30 天的 `(product_id, store_id)` 需求量和门店粒度 ABC。数据服务新增商品粒度最近 30 天需求查询，大屏使用共享函数生成商品粒度等级。

### 批量预测

`forecast_service.get_forecast_all` 使用 `ThreadPoolExecutor` 以配置项 `FORECAST_WORKERS` 限制并发数。每个 future 独立捕获异常并记录日志；最终按照传入的商品顺序和门店顺序组装结果，保证接口输出确定。预测器单例初始化增加锁，避免并发首次加载时重复加载模型。

### 大屏聚合

大屏先计算全量预测，再按 `product_id` 累加预测量和采购建议。缺失的单项预测按零计入并保留历史 ABC 等级。KPI 的 ABC 分布改为直接使用商品粒度最近 30 天需求，避免从门店等级中用“最高优先级”近似商品等级。

### 前端 API 地址

`frontend/js/api.js` 先读取可选的 `window.API_BASE_URL`，并移除末尾斜杠；没有显式配置时保留同源反代逻辑，`file:` 页面回退到本地 8000 端口，3000/5500 仍连接本地 8000。README 增加覆盖配置示例。

### 质量门禁

新增 `pyproject.toml` 统一 pytest/Ruff 配置，新增开发依赖清单和 `.github/workflows/ci.yml`。CI 使用 Python 3.11，安装运行与开发依赖，生成数据、训练模型、执行 Ruff 和全部 pytest。文档中的指标改为当前训练流程的示例结果，并明确重新训练后可能变化。

## 错误处理

- 单个商品/门店预测失败不影响其他结果，返回已有的错误结构并记录完整日志。
- 共享 ABC 函数对空输入和总量为零返回空映射或全 C，不抛出业务无关异常。
- 前端 API 请求继续统一处理非 2xx 响应；显式 API 地址只影响基地址，不改变路径和错误处理。

## 测试策略

- 纯函数测试：ABC 阈值、零值、负值、重复数值和平局顺序。
- 服务测试：批量预测结果顺序、单项失败隔离和 worker 配置。
- API 回归测试：Top 商品预测必须等于全门店汇总，ABC 分布总数等于 SKU 数量。
- 前端静态测试：检查显式 API 地址、同源和本地回退分支的字符串逻辑。
- 交付验证：pytest、Ruff、数据初始化、模型训练、健康检查、主要 API 和前端静态服务器响应。

## 非目标

- 本次不引入数据库、消息队列或新的前端框架。
- 本次不改变预测模型结构和现有响应字段。
- 本次不自动创建 GitHub Pull Request；完成后将推送 `codex/formal-project-optimization` 分支，并报告远程提交证据。
