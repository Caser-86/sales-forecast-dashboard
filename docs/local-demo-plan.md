# 本地完整演示版实施计划

日期：2026-09-22。状态：执行中，M1/T1、M1/T2 共享壳、T3/T4/T5 第一切片、T6 预测分析第一切片、T7 库存试算第一切片、T8 本地角色审批第一切片和 T9 系统诊断第一切片已完成。目标版本：Local Demo V2。

**Goal:** 在 Windows 本机完成销售数据导入、质量检查、预测分析、库存决策、补货审批与导出、版本恢复的完整演示，关键业务步骤无需手工执行命令。

**Architecture:** 延用单实例 FastAPI、原生 JavaScript/ECharts、SQLite 和版本化文件。在现有领域服务外增加管理 API、持久化任务和多页面工作台；演示环境独立存储，数据、模型与库存作为兼容的运行快照切换。

**Tech Stack:** Python 3.11、FastAPI、Pydantic、pandas、PyTorch、LightGBM、SQLite、HTML/CSS/JavaScript、ECharts、PowerShell、pytest、Playwright；Docker Compose 作为另一运行入口。

执行方式：按任务逐项实现、验证和提交；每阶段先验收再进入下一阶段。可采用 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development`。本文件是当前唯一实施路线，不另建重复的路线或完成总结文档。

## 1. 目标和假设

- 主要用途：求职面试，单台 Windows 电脑、单实例服务、浏览器操作，能够在 10–15 分钟内讲清完整业务流程。
- 默认资源预算：4 核 CPU、8GB 内存、无 GPU。这是待实测的设计目标，并非已验证性能承诺。
- 首次安装允许联网；完成依赖安装和演示包准备后，核心演示应能断网运行。首次安装完全离线属于可选打包增强。
- 默认演示使用带来源标签、固定随机种子、固定业务参考日期的生成数据。画面持续显示“演示数据”和业务日期，不能冒充实时业务或真实收益。
- “功能全”指下面范围内的业务闭环。真实供应商下单、ERP/WMS 实时同步、企业 SSO、多租户、分布式部署不属于本版验收。
- 本轮只制定计划；时间、性能指标和新增文件均为建议，不能视为已交付功能。

## 4. 业务和架构约束

### 4.1 数据与模型发布

- 上传默认只产生候选版本。校验失败不改变当前演示状态；限制文件体积、行数、文件类型，文件路径由服务端生成。
- 发布的运行快照引用销售、库存、模型、策略版本，并保存校验结果。所有请求读取同一个已激活快照，防止多指针分别切换造成短暂不一致。
- 训练任务固定输入版本；候选训练不得覆盖活动特征、模型或活动指针。现有训练会激活结果，必须先拆出“训练候选”和“发布”再开放界面按钮。
- 校验版本匹配、商品/门店覆盖、业务日期和库存有效期；旧数据可以浏览，但不允许据此审批新补货计划。
- 延续 30 天预测、时间切分 60/20/20、validation 选策略、test 最终评估。基线胜出是合法结果。
- 指标显示名称、公式、评价窗口、有效样本和单位。不使用没有严格定义的“预测准确率”；情景范围不标为置信区间。

### 4.2 任务与存储

- 长耗时任务通过独立受控子进程运行；SQLite 记录任务、输入版本、阶段、心跳、产物和错误摘要。同一时间只运行一个训练/发布写任务。
- API 返回任务 ID 后由界面轮询；未知真实完成比例时显示阶段和已耗时，不能伪造百分比。
- 重启后把遗留 running 任务标为 interrupted，允许显式重试；不能把中断任务当作成功或自动发布。
- 保留已有不可变草案快照，增加迁移版本、计划版次和事件表。所有迁移先备份，旧数据库可升级并保留旧草案。
- 采用本地演示数据根目录，与用户已有数据隔离。重置只处理受控目录，先备份并让用户确认范围。

### 4.3 计划与角色

- 计划状态：`draft -> submitted -> approved`；`submitted -> rejected`；`draft/submitted -> cancelled`；驳回后创建新的 draft 版次。
- 提交后冻结该版明细；批准不代表已采购、已到货或已同步到外部系统。导出是可审计事件，不改变审批状态。
- 人工调整保存原建议、调整值、原因、操作者和时间。数量非负且为整数，包装/MOQ 不合规时阻止提交或要求按明确规则纠正。
- 修改和审批使用乐观版本号，重复提交/重复审批具备幂等性；服务端拒绝越权和无效状态转换。
- 演示身份为分析员、审批员、管理员。使用本地预置账号与服务端会话；页面切换身份不能冒充服务端权限控制。此功能只在演示配置启用。
- 审批前检查来源兼容性和新鲜度；失效计划允许历史查看、标记导出，但不能新批准。

### 4.4 本地交付

- 主路径为 Windows 原生启动，解决面试现场 Docker 不可用的问题；Compose 继续作为可选验证路径。
- 原生入口优先同源：FastAPI 在独立静态路径托管前端并跳转入口，避免覆盖现有 `/api`、`/health` 和根健康契约。
- 默认绑定 `127.0.0.1`。本地管理接口仍校验会话、写权限和跨站请求；训练参数使用白名单，不接受任意命令或任意磁盘路径。
- 快速演示加载预先验证的模型包；完整训练作为独立可见能力，不在每次开机时运行。
- 保持原生前端，将新增页面拆成独立模块，共享导航、API、状态和样式。按实际变更提取 `dashboard.js` 的共用逻辑。

## 7. 最终演示脚本与发布门槛

1. 一键启动，在总览解释业务日期、生成数据来源和数据/模型版本。
2. 导入错误 CSV，展示行级错误，再导入正确文件成为候选版本；当前画面保持可用。
3. 在模型中心展示真实训练任务和已完成候选的回测，人工发布兼容运行快照。现场长训练可后台运行，明确当前展示的是预先完成的真实结果。
4. 从商品/门店进入预测，解释基线、所选策略、指标窗口及缺失/不足情况。
5. 从缺货风险进入补货试算，调整策略与数量，展示公式并生成草案。
6. 分析员提交，审批员审批，展示修改记录和 CSV，重启后计划仍可查询。
7. 切换库存过期场景，验证补货被阻止；恢复标准场景，展示健康与备份恢复。

发布必须满足：以上流程在浏览器完成；预装环境断网可运行；无伪造实时数据或训练进度；写操作有权限和一致性校验；坏输入不破坏活动数据；启动、迁移、备份恢复和重启经过验证；无未解决的阻塞或高优先级缺陷。

建议验证命令（在对应任务实现后执行）：

```powershell
python -m pytest backend/tests -q --cov=backend/app --cov=backend/common --cov-fail-under=85
python -m ruff check backend scripts
docker compose config --quiet
git diff --check
```

浏览器测试使用现有 `frontend/package.json` 的 `npm run test:e2e`，从 `frontend/` 执行并按 Playwright 配置先准备服务。新增 Windows 启动、断网和参考机器性能测试需单独记录，不能用上述命令替代。
